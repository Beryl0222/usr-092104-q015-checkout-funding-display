# 收银台渠道编排与审计系统

支付平台新规改造的参考实现：后端维护资金渠道类别、用户资格、订单可用性、展示规则版本、风险提示、费用明细、用户主动选择与最终扣款回执；另附一页**键盘/读屏可用**的参考收银台，用于验证真实展示行为。

## 合规设计（规则码贯穿事件、页面、审计报告）

| 规则码 | 约束 |
| --- | --- |
| R-PAY-001 | **结构区隔**：支付工具 / 理财 / 借贷三类资金分组独立成块，借贷不得排在自有资金之前 |
| R-PAY-002 | **禁止默认借贷/理财**：默认项只能落在支付工具；贷款、货币基金、分期不得默认选中或预置勾选 |
| R-PAY-003 | **推荐不越界**：推荐分只允许影响支付工具组内次序，信贷的历史行为高分被组装器结构性忽略 |
| R-PAY-004 | **禁止诱导文案**：发布期扫描“低门槛/秒到账/零利息/人人可借/稳赚/保本”等黑名单 |
| R-PAY-005 | **费用透明**：选择与确认快照含资金性质、费用构成（本金/利息/手续费）、总费用、取消后果 |
| R-PAY-006 | **借款主动确认**：选择信贷/分期必须主动勾选知情确认，确认文案原文随选择事件留证 |
| R-PAY-007 | **灰度证据**：命中规则版本随商户×客户端版本、命中范围、发布人写入每次组装快照 |
| R-PAY-008 | **回滚不变性**：回滚只移动版本指针；已确认订单冻结当时版本、渠道与费用，不可改写 |
| R-PAY-009 | **单次结算**：渠道流水号幂等 + 订单维度二次拦截，重复回调只留证据事件、只结算一次 |

关键边界：合规规则只决定**可展示方式**。余额/份额只从账务提供者只读透传并标注来源，系统不伪造余额；信贷不展示额度，是否获批以资金方审批为准，系统不代授信。

## 目录

- `src/domain/enums.js`：资金分组（自有资金/理财赎回/借款负债）、渠道目录、事件与规则码
- `src/domain/rules.js`：合规引擎——策略草稿校验、展示组合（纯函数）、费用试算
- `src/server/store.js`：仅追加事件存储（JSONL 落盘，事件不可变）
- `src/server/policy-service.js`：规则发布、灰度解析（商户×客户端版本）、回滚
- `src/server/checkout-service.js`：组装→选择→确认→回调→单次结算
- `src/server/audit.js`：一致性审计报告（展示/选择/扣款逐项引用事件 ID 与规则版本）
- `src/server/seed.js`：演示用资格/账务/定价事实源与合规基线策略 v1
- `src/server/http-server.js`：HTTP API + 管理端 + 静态页
- `public/index.html`：无障碍参考收银台（fieldset/radio、aria-live、跳转链接、可见焦点）
- `tests/compliance.test.js`：15 项合规不变量测试
- `contracts/domain.schema.json`：领域事件枚举（新增 4 类事件，与已有 5 类兼容）

## 运行

```bash
npm test      # 16 个测试全部通过
npm start     # http://localhost:8080
```

打开 `http://localhost:8080` 即可操作参考收银台：

1. 选择商户/客户端版本/用户/金额后「组装收银台」——即使推荐分给信贷 999 高分，信贷也停留在独立的「借贷」分组且不预选。
2. 选择银行卡/余额可直接确认；选择信贷必须先主动勾选「借款知情确认」，否则后端返回 403。
3. 确认前可见资金性质、费用构成（含利息与总额）、取消后果；确认后冻结规则版本。
4. 「模拟重复回调」可验证同一流水号不会产生第二次结算。
5. 管理区可尝试发布违规策略（被 R-PAY-001/002/004 拦截）、发布仅 M002×≥8.5.0 命中的 v2 灰度、再回滚。
6. 「生成一致性审计报告」输出每个会话逐条规则核对结论与单次结算统计。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/checkout/compose` | 组装收银台，返回展示快照（含命中版本、灰度证据、费用、被排除渠道及原因） |
| POST | `/api/sessions/:id/select` | 用户主动选择（信贷需 `explicit_ack` + `ack_text`） |
| POST | `/api/sessions/:id/confirm` | 确认付款，冻结渠道/费用/规则版本/取消条款 |
| POST | `/api/sessions/:id/cancel` | 确认前取消，无扣款无费用 |
| POST | `/api/callbacks` | 支付结果回调（幂等；返回是否结算及一致性结论） |
| GET  | `/api/audit` | 一致性审计报告（PASS/FAIL + 逐条证据链） |
| GET  | `/api/events` | 原始仅追加事件流 |
| POST | `/admin/policies` | 发布规则（草稿先过合规校验，422 即违规拦截） |
| GET  | `/admin/policies` | 版本台账（灰度范围、是否当前基线） |
| POST | `/admin/policies/rollback` | 回滚（记录 from→to 与原因，不动历史快照） |

## 客服与审计如何解释一次展示

每次「组装」事件内嵌完整展示快照：命中规则版本、商户与客户端版本、灰度命中范围、分组与排序、默认项、每个渠道的费用与风险提示、被排除渠道及真实原因。客服凭会话/订单 ID 即可回答“这次排序与提示来自哪版规则的哪一条”；审计报告把展示 → 主动选择（含借款确认原文）→ 确认冻结 → 实际扣款串成证据链，金额/渠道/版本不一致即 FAIL。

## 无障碍

参考收银台为无框架单页：语义化 `fieldset/legend` 区分三类资金；原生 radio 支持 Tab + 方向键操作；状态变化经 `aria-live` 播报；首屏「跳转到渠道选择」；所有可操作元素有可见焦点环与明确标签；不依赖颜色单一通道传达风险（同时有文字「借款负债/理财赎回/自有资金」与图标提示）。
